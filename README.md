# 싸준 (ssajoon)

> API 응답 7.9초를 0.22초로 개선한 온라인 알고리즘 문제 풀이 플랫폼

[트러블슈팅](./TROUBLESHOOTING.md)

## 프로젝트 설명

**2026.04 - 2026.06 | FE 1명, BE 1명, AI 1명**

코딩 테스트 준비 과정에서 문제 사이트, IDE, 제출 기록이 분리되어 생기는 맥락 전환을 줄이기 위해 만들었습니다. 전체 프론트엔드를 설계·구현하고 Supabase DB, RLS, SQL, RPC를 설계했습니다. 사용자는 웹에서 문제를 탐색하고 Python·Java·C++ 코드를 작성해 제출하며, 채점 결과와 자신의 제출 이력, 다른 사용자의 풀이를 확인할 수 있습니다.

## 성과 요약

- 문제 통계의 사전 집계와 Trigger 갱신, RPC 최적화로 브라우저 기준 문제 목록 API 응답 시간을 **7.9초 → 0.22초**로 단축했습니다.
- Server Component와 동적 import로 FCP를 **1.5초 → 0.3초**, LCP를 **2.1초 → 0.3초**로 개선했습니다.
- KaTeX·웹폰트·Markdown·반복 prefetch 병목을 제거해 Lighthouse를 **89점 → 100점**, 요청 수를 **84개 → 27개**, 전송량을 **836KB → 210KB**로 개선했습니다.

## 핵심 기능

- **문제 탐색**: 난이도·알고리즘 유형·검색어·정렬·페이지네이션으로 문제를 찾습니다.
- **웹 코드 에디터**: CodeMirror 6 기반으로 Python, Java, C++ 문법과 라이트/다크 테마를 지원합니다.
- **제출과 결과 확인**: 코드 실행·제출, 채점 상태, 실패 테스트케이스, 제출 코드와 결과를 제공합니다.
- **학습 기록**: 제출 이력, 주간 통계, 성능 분석, 다른 사용자의 같은 언어 풀이를 확인합니다.
- **운영 기능**: 관리자 화면에서 문제·예제·테스트케이스·사용자를 관리합니다.
- **사용성 QA**: 사용자 20명을 대상으로 사용성 QA를 진행하고, 발견 이슈를 개선 우선순위로 정리했습니다.

## 기술 구성

| 영역 | 기술 |
| --- | --- |
| Frontend / BFF | Next.js 16, React 19, TypeScript |
| 데이터·인증 | Supabase Auth, PostgreSQL, Supabase RPC |
| 상태·캐시 | TanStack Query, Zustand |
| 에디터·렌더링 | CodeMirror 6, React Markdown, KaTeX |
| UI·배포 | Tailwind CSS, Vercel |

## 설계 포인트

- 공용 문제 데이터와 사용자별 풀이 상태를 분리해 캐시 정책과 갱신 범위를 다르게 가져갔습니다.
- 문제 목록의 정렬·필터·집계는 PostgreSQL RPC로 처리하고, `problem_stats` 사전 집계와 Trigger 갱신 방식을 적용했습니다.
- 문제 본문은 Server Component로 먼저 보여주고, 무거운 코드 에디터는 클라이언트 경계에서 로드해 초기 렌더링 경로를 줄였습니다.
- 제출 성공 시 관련 쿼리만 무효화해 화면 전체를 다시 요청하지 않도록 구성했습니다.

## 실행 방법

```bash
npm install
npm run dev
```

Supabase 프로젝트와 채점 실행 환경 설정이 필요합니다.
